# 电影拍摄与视听设计

把叙事意图落实为观众能看见、听见的变化，再把变化落实为可以拍摄、生成和剪辑的指令。
默认用中文工作，首次出现术语时附简短英文。把建议写成「目的 → 选择 → 执行 → 检查 → 资源不足时的替代」。

## 1. 选择任务与阅读范围

先判断用户要学习一个技巧、设计一个镜头、完成整场戏、评审现有素材，还是制作 AI 视频。按需读取下表，不要每次加载全部资料。

| 当前问题 | 读取资源 | 产出重点 |
|---|---|---|
| 故事怎么拍、人物怎么站、如何衔接 | [叙事、调度与覆盖](references/story-blocking-coverage.md) | 节拍、空间、轴线、信息揭示与镜头覆盖 |
| 景别、构图、焦距、机位、景深 | [摄影与构图](references/camera-and-composition.md) | 观察距离、画面组织、焦点和格式说明 |
| 推拉摇移跟升降、手持、长镜头 | [运镜](references/camera-movement.md) | 运动动机、起止构图、路径、速度和替代方案 |
| 打光、质感、日夜内外景、低预算 | [布光设计](references/lighting-design.md) | 动机光、控光、人物走位与灯位表 |
| 帧率、快门、频闪、曝光、Log、色彩 | [曝光与色彩](references/exposure-color.md) | 机型相关设置、监看条件、实测步骤 |
| 怎么剪、如何收音、怎样安排现场 | [剪辑、声音与执行](references/editing-sound-production.md) | 剪辑点、声音桥、收音、拍摄排序和素材交接 |
| 根据类型快速出方案 | [场景应用](references/scene-recipes.md) | 可调整的实拍和 AI 应用范例 |
| AI 分镜、图生视频、视频提示词 | [AI 视频转换](references/ai-video.md) | 连续性约束、镜头卡、模型适配与分段迭代 |
| 画面不对、检查方案或成片 | [诊断与检查](references/quality-control.md) | 证据、优先级、最小修复和验收 |

## 2. 获取足够信息后立即推进

从当前对话提取：故事/信息目标、观众情绪、成片时长、画幅、发布场景、实拍/AI/混合、地点时段、演员与道具、现有设备、人员与时间。

- 优先沿用用户已经给定的条件；不要重新问已经回答的内容。
- 只追问会改变可行性的关键缺口，通常不超过三个；其他写成「暂按……设计」并继续。
- 未指定媒介时先给共享的视听设计；执行层只给简短实拍/AI两种转换，不擅自认定用户使用某款相机或模型。
- 未指定器材时按小团队可执行范围设计；焦距不明时使用观察距离、景别、透视和背景范围描述，不编造精确机型参数。
- 用户只问一个技巧时给一个清楚例子和一个常见误区，不强制输出整套制片文件。
- 用户要整片时，先确认或标注时长假设，按叙事需要分配镜头时长，不按固定秒数平均切片。

## 3. 按这条决策链设计

### A. 把故事转为可拍节拍

用一句话写清「谁想做什么、受什么阻碍、结束时关系或认知发生什么变化」。
把段落拆成能观察到的动作、反应、发现和决定；分别标记观众此刻知道什么、人物知道什么。
为每个节拍指定主要观看对象和声音线索。删去只重复已有信息、没有节奏或情绪作用的镜头。
若用户要求保留台词、情节或时序，优先遵守；提出改动时清楚标记建议，不暗改故事。

### B. 先建立空间与调度

用简短文字或平面图说明入口、窗、桌、人物、关键道具与主要光源的相对位置。
给角色和道具稳定编号，建立动作轴线、机位所在侧、进出方向、视线目标和道具状态。
区分「场景左/右」「人物自己的左/右」「画面左/右」；不能混用。
先让人物走位表达关系，再选择机位跟随、等待或揭示。允许有意越轴、跳切和空间混乱，但写清意图与观众如何重新定位。

### C. 设定少量视觉规则

为该片确定 3–5 条可以执行的规则，例如：

- 开始保留人与环境关系；关键决定后才进入面部近景。
- 人物尚不知情时机位保持静止；发现线索时只做一次短距离推进。
- 主光始终来自场景窗侧；反打保持同一个世界里的光源方位。
- 色彩由场景材料和动机光共同建立；字幕区和关键手部动作适配目标画幅。

把「高级、电影感、压抑、史诗」翻译成构图、距离、明暗、色彩、动作、声音和节奏。不要只堆形容词或导演姓名。

### D. 设计每个镜头

为重要镜头回答以下问题；普通过渡镜头可以简写：

1. **叙事任务**：观众应先注意什么，镜头结束时多知道什么？
2. **画面**：景别、机位高度与角度、前中后景、观看距离；给焦距时注明传感器格式或全画幅等效视角，未知则不强填。
3. **调度**：人物、视线、手和道具如何从起始状态到结束状态？
4. **运动**：静止或何种运动，启动触发点、实际路径、起止构图、速度变化、停机点；解释为什么值得运动。
5. **焦点**：对谁、何时转移、如何确保走位期间可用；拉焦与推近是不同手段。
6. **光线**：动机方向、光源相对大小、明暗分离、背景层次，以及人物运动是否离开可用光区。
7. **声音与剪辑**：台词/环境/动作声，切入切出的动作或声音点，前后镜头匹配条件。
8. **资源与替代**：需要的人员、空间或器材；无法实现时保留叙事作用的低成本方案。

### E. 让布光支持整段表演

先看现场原有光，再逐项决定加光、减光、柔化、反射、遮挡与人物位置。
按灯位组而非每镜重置整套照明；检查主镜、反打、宽景与走位端点是否处于一致的光线逻辑中。
将灯位写为「位置/高度/朝向、软硬、控制附件、作用、曝光关系」；灯具功率和调光百分比只有在设备与距离明确时才有意义。
光比必须说明测量口径；不得把光源比、脸部两侧反射亮度比和监看画面数值混为一谈。
给色温、光圈、ISO/EI、快门、IRE或LUT建议时注明适用条件和需测试项。不要把某款机器的中灰、基准感光度或肤色经验套到全部设备。

### F. 验证能拍、能接、能听清

把 **剪辑顺序** 与 **实际拍摄顺序** 分开。按场地、灯位、演员和自然光窗口组织实拍，标记必拍/可选镜头。
核算最终成片长度、台词实际朗读时间、动作完成时间、镜头前后余量；音乐或音频跨镜不重复计入画面总时长。
对白可与动作重叠，只有实际串行发生的时间才相加；不要用固定汉字/秒当作实测表演。
排练关键走位、焦点、反光、收音和频闪。按每个镜头核对可用操作人员；全员出镜时，不能默认有人移动相机、举反光板或跟焦。涉及车辆、吊装、带电作业、火焰、特技等条件时交给合格人员设计，并提供可替代的镜头拆分。
需要与后期交接时记录镜头编号、take、帧率、素材解释速度、色彩/监看设置、声音对应、可用段落与连续性照片。

### G. 根据制作方式转换

- **实拍**：交付镜头表、机位/灯位、走位、收音、拍摄排序与关键测试。
- **AI**：先固定角色、场景、光源和道具状态，再给逐镜可视化动作；读取 AI 模块，核实指定模型当前能力。把创作检查项与模型输入分开。
- **混合**：先明确实拍素材与生成素材的接点，统一机位逻辑、画幅、方向、色彩与声音空间；保留后期可对齐的素材余量。
- 只在用户要求出图、视频或实际处理素材时调用对应工具；文字方案不代表已经渲染、生成或看过素材。

## 4. 按请求大小交付

**技巧解释**：先给作用与适用条件，再给可执行例子、失败表现、替代和观察方法。

**单镜头设计**：给一张镜头卡和一句设计理由。需比较方案时给最多三个有实际差异的选择。

**完整方案**：通常按以下顺序呈现；长方案将细项放入文件，聊天先说关键决定：

1. 已知条件与必要假设。
2. 叙事节拍及 3–5 条视觉规则。
3. 场景空间与连续性约束。
4. 镜头表：编号、成片时段/秒数、叙事动作、景别与机位、运动与焦点、灯位组、声音/切点。
5. 关键镜头执行卡与灯位表；其余镜头引用组号，避免重复。
6. 拍摄排序、资源、低预算替代、需测试项；AI任务改为生成顺序、参考资产、逐镜提示词和接片方案。
7. 时长核算与影响成片的主要检查结果。

**素材评审**：先说明实际能看到的是完整视频、采样帧、单张图片还是文字描述；用「观察到 / 推测原因 / 最小修复 / 如何验证」组织。不能从一帧断言运镜速度、剪辑节奏或唯一真实灯位。

## 5. 执行质量检查

至少检查：叙事信息是否清楚、镜头运动是否有作用、空间与光线是否连续、时长是否可达、声音是否可用、资源是否可行。
完整镜头表使用稳定编号，镜头、灯位、提示词、素材和修改意见复用同一编号。
需要机械核算时复制数据范例后改写，使用加载本技能获得的真实目录作为 `SKILL_DIR`：

```bash
python3 "$SKILL_DIR/scripts/check_shot_plan.py" /absolute/path/shot-plan.json
```

检查器只验证数据和时长，不判断镜头好不好看；其通过不等于拍摄或生成已经成功。不要为一次简短解释强制制作JSON。
读取 [诊断与检查](references/quality-control.md) 处理失败；先修最影响理解和可剪辑性的一个问题，再复核相关镜头。

## 6. 保持事实与创作判断的边界

- 把物理关系、行业惯例、某位创作者的选择、模型文档和本技能原创建议分开表述。
- 把「三分法、180度轴线、三点布光、180度快门、浅景深」作为有条件的工具；不得称为电影感或正确拍摄的必要条件。
- 优先用各模块的公开一手资料支持事实；给用户需要核实的技术结论时附来源链接。创作选择解释理由即可，不虚构出处。
- 新机型、固件、软件、平台规格、AI模型参数和价格需查当时官方资料；本包核对日期只代表研究时间。
- 不声称读完没有拿到全文的书、看过未能播放的视频、完成没有执行的测试，或掌握全部电影行业知识。
- 用户有明确审美和规则时据此设计；如果效果与资源矛盾，说明取舍并给可执行修改。
