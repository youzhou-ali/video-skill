# 代码绘制视频：完整细则

本文件是 SKILL.md 第 5 节"代码绘制"的细则。先按 SKILL.md 第 3、4 节完成简报和共享设计链，再按这里的五道关卡做。文中所有路径（`vendor/`、`styles/`、`scripts/`、`examples/`）都相对于技能根目录。

Claude 不生成像素，而是写代码把每一帧画出来：场景代码 → 无头浏览器逐帧截图 → ffmpeg 编码。成片好不好取决于三件事：先想清楚再写（分镜），把风格写成数字（规格卡），看自己画出来的帧（审片）。

## 流程：五道关卡

| 关 | 产出 | 过关标准 |
|---|---|---|
| 1 简报 | 确认过的 brief | 受众、要传达的一件事、时长画幅、素材与事实、音频、风格都有答案 |
| 2 剧本与分镜 | `STORYBOARD.md`，开头是导演卡 | 一个转折；每镜有事件；读点有时间；每个接缝有决定；首尾呼应；每项手法有数字和理由 |
| 3 关键帧 | 2–4 张全尺寸静帧：开场，加与其他场景差别最大的一场；运动复杂时再加最难的 2–4 秒样片 | 风格被认可；画面最满的时刻不溢出、不遮挡；这一帧不能原样搬进别的片子 |
| 4 草稿 | 半尺寸、全细节、带声音的整片 | 自动质检通过；陌生观众审片提出的问题已处理 |
| 5 成片 | 全尺寸 MP4、源码、交付报告 | 接触表过检查清单；整片完整看一遍；响度达标 |

- 用户在场：第 1 到 4 关各停一次等确认。先给对方看，再问；对方没看过的东西不要求确认。一句“可以”就是往下走，同一轮里接着做。
- 流程轻重按规模定，不按用途。60 秒以内、场景少：简报和导演卡一条消息给完，两张静帧后直接出草稿。60 秒以上、多场景、有长旁白或要查资料：每关都停，草稿前先做 animatic（低分辨率、时间准确、带临时声音）。
- 无人值守：取最合理的解读往下做，在交付报告开头写明取了哪种解读。
- 不跳关。分镜没过就写代码、没看接触表就整片渲染，是返工的两大来源。
- 长任务在项目目录放一份 `STATE.md`：现在在哪一关、已定的选择（风格、音乐、配音）、没解决的意见、下一步。续作时先读它，不靠聊天记录。

## 1. 简报：一次问完

已知的不问，缺的一次问清：

- 观众看完要理解或感受到的**一件事**；受众；发布位置
- 时长、画幅（16:9 / 9:16 / 1:1）、分辨率、语言
- 必须精确的内容：产品名、数字、功能说法、Logo、文案。不编造，缺的标“待确认”
- 素材与权利：每项素材的来源和许可；没有就走零外部素材
- 音乐来源由用户定：自己的曲子（要 BPM 和第一拍的偏移）、开放许可的录音、代码合成、或不要音乐
- 旁白：要不要；要的话给 2–3 个候选音色的短样，用户听过再选
- 风格：指定一种，或给参考片

首条消息已经说清内容、时长、画幅和交付物时直接开工，只为会改变成片的缺口问一次。

## 2. 选路线

先定交付物是什么，再定工具。混合流程按镜头注明画面来源。

| 要做的 | 首选路线 | 备注 |
|---|---|---|
| 动态图形、产品宣传、UI 演示 | HTML + CSS/SVG/Canvas，时间轴驱动 | 要工程化可用 HyperFrames（Apache-2.0）或 Remotion（个人和 3 人及以下公司免费） |
| 手绘/水彩卡通、角色短片、MV | p5.js + p5.brush，基于 `vendor/ClaudeAnimationBase/` | 先读它的 `ANIMATION_GUIDE.md`；无独显时水彩填充很慢，改平涂；原角色不可用，自己设计 |
| 数学、知识讲解 | Manim，或 Canvas/SVG 加旁白 | 事实和公式要有来源清单 |
| 像素风 | Canvas 低逻辑分辨率（如 320×180），整数倍放大，关平滑 | 固定调色板 |
| 3D | Three.js（实时）或 Blender（离线） | 灰模只给自己看，给用户的草稿要全细节 |
| 竖屏故事短片（2D 角色 + 3D 世界） | Remotion 里跑 three.js，基于 `vendor/claude-animated-shorts/` | 配音先行，逐词对时 |
| 电影感短片、广告、纪录讲解 | 单个自包含 HTML（Canvas 2D 或 three.js）加离线合成的声音，参考 `vendor/cinecode/references/quick-mode.md`、`film-mode.md` | 60 秒以上改用逐镜渲染的分步流程 |
| 109 种风格里的任何一种 | 照该风格 `demo/` 的引擎和写法 | 先读 `DEMO.md`；演示片的音乐、配音、字体、素材没收入，要换成自己的 |
| 改编已有视频 | ffprobe 探测 → 列出必须不变的要素 → 代码覆画 | 先做 10 秒样片验证同步 |
| 写实画面 | Claude 当导演，视频模型出像素 | 不能称作“纯代码绘制” |

开工前检查环境：`node`、`ffmpeg`、Chrome 或 Playwright，以及要用的库是否已装。要旁白就同时检查配音工具；没有的话在简报里直接说明，让用户选：改成无旁白，或者自己提供录音。风格要求的字体（手写体、连笔字、衬线体）也先查有没有，没有就在规格卡里写明用什么替代。从网上下载的演示代码可能不允许在工作区运行，这时读它的写法自己实现，不要设法绕过。装不了就退回原生 Canvas 2D/SVG，附录的渲染脚本就是这条路线，任何环境都能跑。

## 3. 风格规格卡：用数字，不用形容词

先到 `styles/INDEX.md` 选一种现成风格，读它的 `STYLE.md`，再按下面的格式写成这支片子自己的规格卡。用户给的风格名不在目录里时，查 `vendor/cinecode/styles/aliases.json`；还找不到，就按下面从零写。

“高级、流畅、酷”无法检验。动手前写一张规格卡：

- 媒介一句话（例：暖色纸上的两色丝网印刷）
- 色板：3–5 个十六进制色；信号色只给一个元素；避免纯黑纯白
- 字体：一到两种，写明字号阶梯
- 缓动：具体曲线（例：`cubic-bezier(.2,.8,.2,1)`），写明哪些元素允许过冲
- 节奏：交错间隔几帧，镜头典型时长
- 镜头怎么相接：擦除、形状生长、匹配剪辑；不要一律淡入淡出
- 质感：纸纹、颗粒、错位的具体参数
- 帧感：纸感约 12fps、手绘一拍二、UI 顺滑。成片容器默认 30fps，低帧感靠把 t 量化实现
- 禁用清单。默认禁：粒子爆发、镜头光晕、霓虹辉光、RGB 分离、故障效果、处处回弹、重复画面内容的文字

有参考片时先测量再模仿。把参考片抽帧拼成接触表（附 C），按运动、景深、质感、角色、光照、描边、调色各写一份数值报告：色值、亮度分位、每帧位移、模糊半径、线宽。写数字，不写形容词。之后拿自己的帧和参考帧并排比。

防模板化：

- 示例场景、测试场景、预设都是脚手架，出第一批静帧前删掉。每个场景为这个故事而建。
- 每张预览帧自问：它能不能原样放进另一部片子？能就重做。
- 没有默认字体和默认色板。蓝紫色占画面三成以上、霓虹、灯塔、飘浮气球这类生成式作品的惯用选择，有来自故事的理由才用。
- 除非要的就是抽象片，不拿抽象图形顶替主体。

按“这一镜要传达什么”选动效，不按“哪个好看”：

| 目的 | 常用动效 |
|---|---|
| 吸引注意 | 预备动作、弹性过冲、缩放弹出、遮罩揭示 |
| 解释 | 交错出现、弧线运动、跟随动作、运动层级 |
| 对比 | 柱状图竞速、环形进度、图表形变 |
| 顺序、流程 | 交错、逐字出现、遮罩揭示、焦点交接 |
| 强调 | 脉冲、高亮扫过、圈出、挤压拉伸 |
| 转场 | 擦除、推移、光圈、交叉淡化、缩放弹出 |
| 数据证明 | 数字滚动、柱条生长、线条绘制、点阵重组 |

大幅镜头运动只留给揭示问题或结果的时刻；讲解图示时镜头稳住，留出阅读时间。

讲解片开头 5 秒：0–1 秒抛出问题或反直觉的结果，1–3 秒给线索，3–5 秒给承诺并留可读的停顿。每屏只讲一个主张。

## 4. 分镜（STORYBOARD.md）

### 先写剧本

- 先发散再收敛：写 10 个角度，丢掉最先想到的 3 个，留 3 个出人意料但成立的，选 1 个并写明理由。可以让一个没看过上下文的子 agent 只读用户的第一句话，猜 5 部最可能做出来的片子；自己的角度和其中某条撞了就换。
- 一个转折：先写清之前和之后（逆转、揭示、变形、临界点、反差）。先写结尾，结尾需要的东西在前三分之一埋好。
- 旁白只说画面说不了的。画面已经演了的不再讲；结尾要靠一句话才看得懂，就改画面。
- 旁白停时画面接力，画面停时声音接力，两者同时空着就是死区。
- 写完朗读计时，再删掉约三成。
- 真实人物和事件：每条事实有来源，标已证实或未证实；证实不了的删掉，或写明据称。
- 禁用套话：破折号、否定再肯定的句式、反问开头、三个抽象词排比、口号式结尾。

旁白密度按类型选：

- 电影感、氛围、广告：词少。英文口径是 15 秒不超过 20 词，30 秒 40 词，60 秒 80 词。
- 竖屏故事短片：旁白几乎不停，英文约每秒 3.7 词。公式：一句当事实说出的荒诞钩子（不铺垫，没有片头、logo、行动号召，人声在头几帧就开始）→ 一两句交代时间、地点、人物 → 3–6 拍逐级升级 → 转折，用一个日常类比讲清机制 → 一两句回扣开头，停在最后一个词上。
- 中文没有现成口径，以实际配音时长为准。

### 导演卡

决定全片手法的唯一位置，放在分镜最前面。每一行都要有数字，和一条来自这个故事的理由，不写“电影感”这类空词：梗概与转折、观众悬念、2–4 个重点时刻、每类对象怎么画以及哪里可能显得廉价、色板与光线变化、形式（一镜到底或剪辑）、镜头与运动、节奏（BPM 与镜长）、转场、字体、音乐与声音、结尾、后期。

### 分镜

先写分镜再写代码。结构：

- **一句话梗概**：谁想要什么，但是……，所以……
- **世界**：场景、色板、光线；色彩随章节变化，结尾回到开头的色调
- **母题**：会反复出现、逐次升级、最后回收的元素
- **情绪弧线**
- **镜头表**，每镜一行：

| # | 时间 | 画面 | 事件 → 反应 | 读点及各自时间段 | 镜头运动 | 出镜转场 | 精确文字/素材 |
|---|---|---|---|---|---|---|---|

规则：

- 每镜首尾之间必须有变化（想要、发现、尝试、失败、反应、得到），一镜一个焦点动作。
- 开场第一帧就在动，以动作开头：不放静态标题，不从黑场淡入，标题和 logo 排在动作之后。有旁白时第一句在 2 秒内开始。
- 末帧停约 1 秒；结尾呼应开头（同地点或同动作，但有所改变）。
- 有音乐时，切点和重击落在拍点上，大变化放在小节线。先把 BPM 和第一拍偏移写进配置。
- 长片分章：每章固定一个场景，章内靠镜头运动而不是换景，章间用明显的转场。
- 读点放不下就加长镜头或删读点，不要压缩。
- 镜头数 = 时长 ÷ 平均镜长：快节奏约 4 秒，标准约 6 秒，沉静 8–12 秒。15–30 秒的片子 4–8 镜，约 60 秒 5–15 镜。
- 节拍各有时长：开场 1–1.5 秒，铺垫 3–6 秒，变化 2–3 秒，转折 1–3 秒，静默 1–1.5 秒，结尾 2–4 秒。镜长不要整齐划一，连续五镜以上长度相近就是节奏问题。
- 镜头运动写成一行：运动名、秒数、速度加缓动、目标。例：推近，3 秒，慢、先缓后缓，朝向人物。

## 5. 时间：替观众着想

这是最常出错的地方。

- 为每个镜头按顺序列出“读点”，也就是观众必须看懂的事。每个读点需要三段时间：找到它、理解它、停留。小的、远的、快的、暗的东西要更久。
- 一次只读一件事。因果分先后：先事件，后反应，反应给足时间。
- 动作本身可以快，含义要停留。过场快带，重点放慢。匀速等于平淡。
- 先引导视线（角色目光、镜头移动、亮度、运动），再让重点出现。
- 镜头长度由读点数量决定。量级参考：约 2.8 秒放 7 个读点还看得清，同样内容压到约 1.3 秒就看不懂了。
- 参考时长：简单形状至少 0.5 秒，新出现的东西 1.5–3 秒。屏幕文字每张不超过 6 个词，停留不少于 0.6 秒加每词 0.25 秒。全片 2–4 个重点时刻，停留等于阅读时间加 1.5 秒，这时周围画面安静。
- 安全区：9:16 上方 12%、下方 20%、右侧 10% 不放文字和关键动作；1:1 和 4:5 四周留 6%；16:9 留 5%。
- 字幕时间取自旁白的实际音频，不按脚本估算。

## 6. 让画面活起来

- 预备 → 动作 → 跟随或过冲 → 稳定。几乎不存在匀速运动。
- 挤压拉伸时保持体积；生物走弧线；重的东西慢启慢停，轻的会弹。
- 错开时间：眼睛先动，身体跟上，附件拖后。避免左右手、多个角色完全同步。
- 夸张。关键姿势单看静帧就要能读懂，剪影清晰。
- 表情和状态不硬切：先预备（眯眼、压缩），再过冲落定。
- 不出现死寂：待机动作、镜头轻微漂移、环境微动。次要动作不抢主动作。
- 主体要够大。远景小人只用来交代环境。
- 镜头运动不算动作。把相机固定后画面几乎不变，这一镜就不合格：主体自己要在做事。
- 动作的意义在于位移时（跳远、冲刺、飞越），镜头不要跟着主体走，否则横向位移被抵消，看起来像原地上下。跟拍只用在路途上，到了关键动作之前先停住机位。
- 动作的意义在于位移时（跳远、冲刺、飞越），镜头不要跟着主体走，否则横向位移被抵消，看起来像原地上下。跟拍只用在路途上，到了关键动作之前先停住机位。
- 停留镜头加缓慢推近（每帧约 0.15–0.35%），不要连续多帧完全静止。爆发式运动用缓出：第一帧最快，8–10 帧内衰减。冲击抖动在约 7 帧内衰减完。
- 道具要一眼认得出。离镜头太近会变成色块，被画面边缘切掉会变成不明物，结构只画一半会被看成别的东西（只有一根绳子的秋千像是吊着）。旗帜、招牌、服饰要符合年代和地点。
- 能演出来的不写字；文字不重复画面已经说了的事。宣传和讲解片需要文字时，保证字号、对比度和停留时间。
- 画面里出现的数字要和画面实际做的事一致：写“距离 ×1.4”，代码里就让距离乘 1.4，而不是把速度乘 1.4。
- 画面里出现的数字要和画面实际做的事一致：写“距离 ×1.4”，代码里就让距离乘 1.4，而不是把速度乘 1.4。

UI 与产品镜头：

- 特写（一个按钮、一行输入）承担主要叙事，整窗全景只留给高光时刻。
- 过程类镜头（打字、内容生成）5–9 秒，点击类 2–3.5 秒，两者交替。动作在切入后 0.3–0.8 秒开始，结果停 0.5–1 秒。
- 界面自己动，不画鼠标在目标之间移动。文字约每秒 12–13 个字符打出。演示内容用可信的名字和数字，不用灰块占位。
- 结尾一行文案加静态 logo，停 2.5–4 秒，不超过 4 秒。高潮处不加抖动和闪光。

## 7. 转场与连续性

- 片头进入、每个切点、片尾离开都要有决定，默认做法随类型不同：手绘卡通每个接缝设计转场；电影感以硬切为主，切在运动最快的那一刻；竖屏故事短片少切，用连续运镜从一个主体带到下一个。
- 转场有含义：溶解表示时间，甩镜表示能量，匹配剪辑表示联系。装饰性的通用转场会削弱片子，同一种设计转场不连用两次。
- 可选：笔刷或形状擦除、光圈、甩镜、形状或动作匹配剪辑、动作中切、镜头运动延续到下一镜、淡到纸色或黑。按故事选，不要每次同一种。
- 镜内变化也算转场：道具沿弧线进出，不凭空出现。
- 跨镜保持角色造型、色板、运动方向、道具状态。循环片首尾帧一致。
- 画中画（屏幕、照片、接触表的格子）：镜头推进去之前，里面的内容就要开始播放，推进前后主体位置连续；镜头离开后，它回到自己的静帧。在分镜里给每个画中画写明它的播放时间段。
- 画中画（屏幕、照片、接触表的格子）：镜头推进去之前，里面的内容就要开始播放，推进前后主体位置连续；镜头离开后，它回到自己的静帧。在分镜里给每个画中画写明它的播放时间段。
- 切点两侧方向和速度一致；主体位置与视线落点对齐到画幅的十分之一以内；模糊帧里不硬切。
- 参考时长：甩镜 0.2–0.35 秒，图形转场 0.45–0.6 秒，溶解 0.4–1.5 秒，匹配剪辑后留 0.3–0.6 秒稳定。声音可以先于画面进来（提前 0.3–1.5 秒），或拖到下一镜上。

镜头运动：

- 先有动机：推是紧张或重要，拉是释放或揭示，横移是旅途，升降是规模，环绕是审视，手持是临场，固定机位是让主体或光线去动。
- 一镜一个主运动，最多加一个辅助运动。相邻两镜的运动、景别、方向至少一项不同。
- 速度用数字：慢是主体大小每秒变化不超过 10%，或横穿画面 6 秒以上；中是 10–25%，或 3–6 秒；快是超过 25%，或 1.5–3 秒。
- 序列里的镜头切入时已经在动，切出时还在动。开场镜头用缓出，不用缓入。
- 大招全片只用一次：滑动变焦、定格、对比硬切、变速。
- 真 3D 运动（推拉、升降、环绕）有视差，变焦会把画面压平。

## 8. 工程铁律

1. **画面是时间的纯函数**。`renderAt(t)` 对同一个 t 永远画同一帧。不存跨帧状态，不用计数器、`Math.random()`、`Date`、定时器、逐帧积分的物理。这样才能乱序渲染、并行、断点续渲、单帧重画。
2. 随机用种子：`hash(i)`。要手绘抖动，就让种子每秒变 12 次；静止物体用固定种子，否则会无故抖动。
3. 每个镜头重绘整帧，包括背景。
4. 字体和图片加载完再画第一帧。库放本地，不依赖 CDN。
5. 用 GSAP、CSS 动画这类基于真实时钟的东西时，改成 seek 到 t（暂停时间轴后按 t 定位），或在渲染时把 `performance.now` 和 `requestAnimationFrame` 换成每帧推进 1/fps 的虚拟时钟。
6. 先测单帧耗时再决定复杂度。形状和笔画几百个可以，几千个太多；用更少、更大的形状。
7. 防 NaN（退化的几何）。页面报错一律当真问题处理。
8. 结构：`config`（时长、fps、bpm、色板）、共享工具与角色、每章一个文件；镜头函数签名统一为 `(t, lt, dur)`，即全片时间、镜头内时间、镜头长度。

## 9. 审片循环

每个镜头做完就看，不攒到最后。三种图：

- **接触表**：每镜至少首、中、末三帧；整片每秒或每拍一帧。
- **条带**：关键动作，以及每个转场前后 0.5 秒的连续帧。
- **裁切**：承载剧情的脸、手与道具的接触点、小字。

对照检查：

- 读点：每件事来得及看懂吗？有没有两件事叠在一起？
- 运动：有预备和跟随吗？有跳变吗？各部位是不是同时动？姿势够夸张吗？
- 稳定：静止元素有没有无故抖动？
- 接触：脚踩地，手握住物体，没有穿模。
- 文字：溢出、重叠、裁切、字体回退、过小、停留不够。
- 规则：违反禁用清单了吗？有没有黑帧、空白停顿、死寂段落？
- 转场：每个接缝都处理了吗？
- 开场：0、0.5、1、1.5、2 秒五帧，相邻两帧明显不同吗？
- 归属：这一帧放进别的片子也成立吗？成立就是模板感。
- 表情：每种表情状态单独裁切看一遍。失落和生气、专注和不耐烦，差别只在眼皮的倾斜方向，很容易画反。
- 最小尺寸：主体在画面里最小的时候（画中画、缩略图、手机竖屏）还认得出吗？
- 末帧：末帧上每个元素都是分镜要求的最终状态吗？离开后该复位的东西复位了吗？

草稿出来后做一次陌生观众审片：起一个没参与制作的子 agent，只给它成片的接触表和测量数字，不给分镜和意图。让它写出最大的三个问题，每个带时间点、对应帧、最小改法。标成必须修的先修。

模仿参考风格时，自己的帧和参考帧并排，按调色、光照、描边、质感、角色、景深、构图各打 0–10 分，附带帧号的修改清单。每轮用一个新的审片 agent，它不带上一轮的成见。

审片图控制在一百万像素以内，看接触表而不是一张张看全尺寸帧，日志写进文件，不贴进对话。

修完再看一遍。没看图就不要“改得更好一点”。

- 每改一处都把 qc.py 全部重跑一遍，不只跑和这处有关的那一项。一处修改会牵动别处：缩短笔影后，开场的运动量就不够了。
- 审片意见先对照风格的 `STYLE.md` 再采纳。和风格前提冲突的建议（例如让一笔画里已经画好的墨迹自己飘动）不照做，在回复里说明理由，另找一种能解决同一问题的改法。
- `qc.py action` 对细线风格（一笔画、单线、线稿）偏严：主体是一根细线时，像素变化本来就小。数值接近阈值时先看条带再决定，结尾有意的静止要在交付报告里写明。

## 10. 渲染与交付

- 先出半尺寸草稿，用户确认草稿后才渲全尺寸。草稿是全细节加完整声音，只是分辨率减半；白模不拿给用户当草稿。整片渲染尽量一次到位。
- 像素单位的参数（线宽、模糊半径、颗粒）按输出高度缩放，否则草稿和成片观感不一致。胶片颗粒会让文件体积成倍变大。运动模糊、胶片色、画面抖动这类后期默认关，由用户选。
- 按输出尺寸绘制，默认 30fps。
- 长片按场景分段编码成参数一致的 MP4，用 concat demuxer 加 `-c copy` 拼接，最后 `-c:v copy` 加音轨。交叉淡化放在段内，不在成品段之间做。
- 帧用 JPEG（质量约 92）直接管道给 ffmpeg。输出先写临时名，ffmpeg 正常退出后再改名。
- 音频用 ffmpeg 封装，不从浏览器录。用 `-t` 显式给时长，不用 `-shortest`。
- 改一个镜头只重渲那一段。
- 合并音轨时显式写 `-map 0:v:0 -map 1:a:0`，有些渲染器会自带一条静音音轨。
- 渲染前看磁盘空间。超过约两分钟的渲染，中途报进度。
- 交付报告包含：MP4 路径与规格；分镜；风格规格卡；素材和音频的来源与许可；哪些是代码画的、哪些是外部素材或模型生成、哪些是人工决定；未核实的事实；两个最弱的时刻及改进方案。

修改意见的处理：

- 一轮意见合并处理。先记下用户夸过的部分并锁定，改别处时不动它。
- 每条意见先诊断原因，换成具体数字再改（“慢一点”变成“这个推近从 2 秒改到 3.2 秒”）。只改被指出的地方。
- 回复时每条一行：已改、换了做法（为什么）、没改（为什么）。
- 草稿后最多两轮。两轮还不对，回到分镜重新定方向，不要继续打补丁。
- 用户喜欢的片子可以存成格式说明：媒介与风格、调色逻辑、字体、镜头与节奏、开场与结尾、声音语言，不含具体内容。下一支片子沿用格式，故事、文字、画面、音乐全部重做。

## 11. 音频、旁白、字幕

- 细则见 `vendor/cinecode/references/sound.md`；可直接改用的合成音效、乐器、混音代码在 `vendor/claude-animated-shorts/templates/audio/`。
- 声音从第一版草稿就有，不是最后补的。每个场景有环境底噪，画面里每个物理动作有对应的声音，无声的动作要有理由。
- 音乐：配置里写 `bpm` 和 `offset`，拍点时刻 = offset + n × 60 / bpm。选每拍是整数帧的 BPM：30fps 用 90、100、112.5、120，24fps 用 80、90、96、120、144。
- 旁白先行：讲稿定稿 → 生成配音 → 语音识别出逐词时间戳并手工校正 → 画面和音效都按词对齐，视觉反应落在对应词之前 0–3 帧。字幕和画面共用同一条时间轴。画面时间锁定后再做声音，之后改时间就要重做声音。
- 旁白不直接用原始 TTS：做清理（高通约 90 Hz、轻压缩），每句调到同一响度，再按故事加空间感。
- 同步：冲击声的瞬态对准接触帧；嗖声的峰值在动作到达前 2–3 帧；上升音在提示点结束。
- 电平：旁白说话时其他声音比它低 8–10 dB；环境底噪比旁白低 20–30 dB；重要冲击比底噪最响处高 6–8 dB。话多的段落用约 6 dB 的浅压低。
- 静音要设计：由一个声音收尾，之后留一点房间底噪，不用数字零。大高潮前让底噪先降 0.3–1.5 秒。
- 母带：−14 LUFS（±1），真峰值不高于 −1 dBTP，48 kHz，两遍 loudnorm（附 C）。各场景响度偏离中位数超过 3 LU 的，要么修，要么说明是有意的。
- Claude 能测量声音，但听不到。每次交付都请用户用耳机和手机扬声器各听一遍，并列出要重点听的秒数：每个转场、最响的场景、旁白每一句、被测量标出的地方。
- 歌词 MV：用表演演出歌词的含义。需要歌词字幕时给它留固定的安全区。

## 14. 常见失败速查

- 没分镜直接写代码；没看帧就整片渲染
- 所有动作同速，事件叠在一起，没有停顿
- 关键时刻一闪而过
- 主体太小，或和背景对比不足
- 表情或状态瞬间切换；线性移动；全体同步
- 满屏硬切，开头结尾突兀
- 文字溢出、重叠、过小、停留不够；字幕到后段失步
- 用了 `Math.random` 或跨帧状态，导致帧间闪烁、并行渲染结果不一致
- 镜头没重绘背景，留下残影
- 时长超出要求；音轨近乎静音却没人听过
- 每个镜头一个世界，彼此无关
- 镜头在动，主体没在做事
- 镜长整齐划一，节奏从头到尾一个样
- 示例或脚手架场景留在成片里；蓝紫配色、霓虹这类惯用选择没有理由
- 停留镜头完全静止，被看成卡住
- 道具被看成别的东西；文字落在平台按钮的安全区里
- 声音最后才加，音效晚于画面
- 用变焦冒充推拉，画面没有视差

## 附 B：最小渲染脚本（原生 Canvas 路线，已实测）

场景页约定：暴露 `window.renderAt(t)` 和 `window.SCENE = {W, H, FPS, DURATION}`。直接打开是循环预览，渲染器带 `?render=1` 打开。

`scene.html`：

```html
<!doctype html><meta charset="utf-8">
<style>html,body{margin:0;background:#111}canvas{display:block}</style>
<canvas id="c"></canvas>
<script>
const W = 1920, H = 1080, FPS = 30, DURATION = 4;
const cv = document.getElementById('c'); cv.width = W; cv.height = H;
const g = cv.getContext('2d');
const clamp = (x, a = 0, b = 1) => Math.min(b, Math.max(a, x));
const seg = (t, a, b) => clamp((t - a) / (b - a));           // t 在 [a,b] 内的进度 0..1
const easeOut = x => 1 - Math.pow(1 - x, 3);
const backOut = x => 1 + 2.70158 * Math.pow(x - 1, 3) + 1.70158 * Math.pow(x - 1, 2);
const hash = i => { const s = Math.sin(i * 127.1 + 311.7) * 43758.5453; return s - Math.floor(s); }; // 确定性随机

const SHOTS = [                                               // 每镜：起止时间 + draw(t, lt, dur)，重绘整帧
  { a: 0, b: 2, draw(t, lt, dur) {                            // 圆点弹入
      g.fillStyle = '#F4EFE6'; g.fillRect(0, 0, W, H);
      g.fillStyle = '#D9482B'; g.beginPath(); g.arc(W / 2, H / 2, 160 * backOut(seg(lt, .2, .9)), 0, 7); g.fill(); } },
  { a: 2, b: 4, draw(t, lt, dur) {                            // 圆点扩张成底色（形状匹配转场），星点交错出现
      g.fillStyle = '#F4EFE6'; g.fillRect(0, 0, W, H);
      g.fillStyle = '#D9482B'; g.beginPath(); g.arc(W / 2, H / 2, 160 + 1200 * easeOut(seg(lt, 0, .6)), 0, 7); g.fill();
      for (let i = 0; i < 40; i++) { const p = easeOut(seg(lt, .5 + hash(i) * .8, 1 + hash(i) * .8));
        g.fillStyle = `rgba(244,239,230,${p})`; g.beginPath(); g.arc(hash(i + 100) * W, hash(i + 200) * H, 9 * p, 0, 7); g.fill(); } } },
];
window.SCENE = { W, H, FPS, DURATION };
window.renderAt = t => { const s = SHOTS.find(s => t >= s.a && t < s.b) || SHOTS.at(-1); s.draw(t, t - s.a, s.b - s.a); };
if (!location.search.includes('render')) {                    // 直接打开=循环预览；渲染器带 ?render=1 打开
  const t0 = performance.now();
  (function loop() { renderAt(((performance.now() - t0) / 1000) % DURATION); requestAnimationFrame(loop); })();
}
</script>
```

```js
const { spawn, execFileSync } = require('child_process');
const fs = require('fs'), path = require('path');

const arg = k => (process.argv.find(a => a.startsWith(`--${k}=`)) || '').split('=').slice(1).join('=') || null;
const scene = path.resolve(process.argv[2]);
const out = arg('out') || 'out/video.mp4';
fs.mkdirSync(path.dirname(path.resolve(out)), { recursive: true });

(async () => {
  const opts = { args: ['--no-sandbox', '--force-color-profile=srgb'] };
  const browser = await chromium.launch(opts).catch(() => chromium.launch({ ...opts, channel: 'chrome' }));
  const page = await browser.newPage();
  page.on('pageerror', e => { console.error('PAGE ERROR:', e.message); process.exitCode = 1; });
  await page.goto('file://' + scene + '?render=1');
  await page.waitForFunction(() => window.renderAt && window.SCENE);
  await page.evaluate(() => document.fonts.ready);          // 字体就绪后再画第一帧
  const S = await page.evaluate(() => window.SCENE);
  await page.setViewportSize({ width: S.W, height: S.H });
  const shot = async t => { await page.evaluate(t => window.renderAt(t), t); return page.screenshot({ type: 'jpeg', quality: 92 }); };

  if (arg('sheet')) {                                        // 接触表：指定时刻的帧拼成一张图
    const ts = arg('sheet').split(',').map(Number), dir = fs.mkdtempSync(path.join(path.dirname(path.resolve(out)), 'sheet-'));
    for (let i = 0; i < ts.length; i++) fs.writeFileSync(path.join(dir, `${String(i).padStart(3, '0')}.jpg`), await shot(ts[i]));
    const cols = Math.min(4, ts.length), rows = Math.ceil(ts.length / cols);
    execFileSync('ffmpeg', ['-y', '-v', 'error', '-i', path.join(dir, '%03d.jpg'), '-vf', `scale=640:-1,tile=${cols}x${rows}`, '-frames:v', '1', out]);
    fs.rmSync(dir, { recursive: true });
  } else {                                                   // 成片：JPEG 帧直接管道给 ffmpeg，不落盘
    const from = +(arg('from') || 0), to = +(arg('to') || S.DURATION), n = Math.round((to - from) * S.FPS);
    const tmp = out.replace(/\.mp4$/, '.part.mp4');
    const a = arg('audio') ? ['-ss', String(from), '-i', arg('audio'), '-map', '0:v', '-map', '1:a', '-c:a', 'aac', '-t', String(to - from)] : [];
    const ff = spawn('ffmpeg', ['-y', '-v', 'error', '-f', 'image2pipe', '-c:v', 'mjpeg', '-framerate', String(S.FPS), '-i', '-', ...a,
      '-c:v', 'libx264', '-crf', '18', '-preset', 'veryfast', '-pix_fmt', 'yuv420p', tmp], { stdio: ['pipe', 'inherit', 'inherit'] });
    const done = new Promise(r => ff.on('close', r));
    for (let i = 0; i < n; i++) if (!ff.stdin.write(await shot(from + i / S.FPS))) await new Promise(r => ff.stdin.once('drain', r));
    ff.stdin.end();
    if (await done !== 0) throw new Error('ffmpeg failed');
    fs.renameSync(tmp, out);                                 // ffmpeg 正常退出才改成正式文件名
  }
  await browser.close();
  console.log('wrote', out);
})().catch(e => { console.error(e); process.exit(1); });
```

用法：接触表用 `--sheet` 传一串时刻；条带就是把时刻取密（例如转场前后每 1/15 秒一帧）；分段渲染用 `--from` 和 `--to`。同一时刻渲两次，文件应当逐字节相同，不同就说明场景里有非确定性的东西。
